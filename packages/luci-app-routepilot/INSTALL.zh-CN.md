# imOK 安装、升级与恢复

当前安装状态统一见[项目 README](../../README.md)。支持验证范围为 GL-MT6000 / ARM64 / OpenWrt 24.10；不是路由器固件，不能用刷写固件上传。其他型号、架构和 WireGuard 实际切换未验收。

## 本版公开分享包

`imOK-0.2.37-1-install-kit.zip` 包含完整插件 IPK、公开源码、使用／安装说明、更新记录、许可与校验文件，适合网盘保存或分享；不含第三方 WARP 运行环境。已有兼容环境直接升级 IPK，解压后先阅读 `开始阅读.md`。它与下方历史“含运行环境的个人首次安装包”是不同内容，不能混用流程。

## 安装矩阵

| 情况 | 操作 |
| --- | --- |
| 新设备，没有运行环境 | 先安装插件，在 WARP 安装与更新检测环境；受支持平台可准备官方组件后单独确认，真实首次安装仍待独立设备验收 |
| 已有 `/opt/routepilot/runtime` | 只升级当前 IPK，保留原注册与配置，不重装运行环境 |
| 缺系统依赖或 xray | 从设备当前固件匹配的软件源安装；不使用强制依赖或其他固件的内核包 |
| 想换新路由器 | 导出非凭据配置，新设备独立登录；导入后保持关闭，核对入口、出口和接管范围后手动启用 |

自动准备预发布流程需约 1.6 GB 可用存储；历史手动包至少准备 500 MB 可用存储和独立可恢复的管理入口。这里所说的历史个人完整包另含未注册运行环境，与本版公开分享包不同；公开分享包不捆绑第三方二进制、身份或私人配置。

## 首次使用：插件内官方组件准备（预发布）

1. 安装本版 IPK，进入 imOK → WARP 安装与更新。
2. 查看自动检测结果；只支持当前标明的 ARM64 OpenWrt 24.10 环境，不强行安装到其他平台。
3. 点击“自动下载并准备安装”，系统从官方来源取得并校验组件；下载本身不会安装或启动隧道。
4. 文件准备好后单独确认安装。安装成功后，登录自己的账户、选择已有出口和接管范围，最后手动开启。

真实首次安装与 APT 升级尚未完成独立实机验收，因此本版按预发布提供。已有环境使用更新路径，不能被首次安装覆盖。参阅 [WARP 维护说明](../../docs/WARP_RUNTIME.md)。

## 高级：历史手动包首次安装

以下历史完整包流程仅适用于已经自行合法准备齐运行环境与校验文件的安装目录；GitHub 下载不包含第三方运行环境包。此段是历史离线方式，不是本版默认安装入口。不要在只有公开源码或 IPK 的目录直接运行此流程。

1. 解压完整 ZIP，把同一个安装目录放到路由器，不混入其他 IPK。不要在 Mac/Windows 上运行脚本。
2. 在路由器管理员 shell 运行 `sh install-router.sh --check`，只做平台、文件校验与空间检查。
3. 确认首次安装后运行 `sh install-router.sh --install`。已有运行环境会拒绝覆盖。
4. 通过当前 IPK 更新插件后，进入 Cloudflare 配置中心登录自己的账户、读取出口、选择范围，再手动开启总开关。

安装不是跨步骤事务。运行环境已解压但 IPK 失败时，先排查依赖，不删除原注册目录盲目重试。脚本只清理自己尚未提交的临时目录。完整旧包保留其当时版本，不能宣称它已包含当前修复。

## 正常升级

先保留当前 IPK、私有配置备份和身份/配置哈希。只上传当前 IPK 或在设备运行 `opkg install /已校验的新版本.ipk`；可能短暂重连。不要执行重注册、删除运行环境或恢复整份旧系统设置。升级后刷新或重新登录管理页以更新旧会话菜单，核对显示版本、原出口、入口偏好、设备范围和 HTTPS，旧页面不能在后台自动换脚本。

规则管理中的个人新增与排除独立持久保存，普通插件更新和订阅更新不会清空；相关文件已纳入系统升级保留范围。当前 v3“导出配置”不包含这些个人覆盖，换设备前需另行备份，不能把普通设置导出当作完整规则迁移。

失败时使用备份的上一版本 IPK 明确降级并核查当前运行态；配置未变且没有新数据格式变化时才可按记录回滚。不要为回滚直接清空系统防火墙或覆盖 network/firewall/dhcp、SSR 配置。

## 恢复阻断

入口事务、持久恢复阻断、历史应用结果和恢复审计目录属于故障证据。固件保留清单包含这些证据；新恢复请求有启动实例和短时确认限制，不能跨重启自动重放。

完整原事务、原出口和当前客户端入口一致时，配置中心显示“受控恢复原入口并验证”。重新读取状态，输入 RESTORE 并确认后，后台只恢复原事务入口，在撤回接管后重连并核对原预期出口；验证、存储或上下文检查失败会继续阻断。操作过程中可能宽带直连。总开关关闭时也会临时启动客户端验证，完成后仍保持关闭、不接管设备；只有明确确认才执行。成功会保存原证据和解除结果。

按钮不可用时，不删除 `endpoint-recovery-block.json`、`endpoint-transaction.json` 或 `endpoint-applied.json`。先确认存储空间、文件可读性、当前组织/出口 UUID、原事务来源及客户端状态；保存受限的原始证据。证据损坏、缺基线、外部修改入口或出口不一致时，自动恢复会拒绝；需按该设备的私有备份与原安装记录制定人工恢复，不能猜测或伪造 baseline。若管理链路也受影响，先通过已准备的独立有线/本地入口处理。

本轮自动化或隔离检查不代表真实断电、固件升级、多 LAN 或手机速度通过；每一类以实际验收记录为准。
