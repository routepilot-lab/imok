# imOK 安装、升级与恢复

以下按运行 OpenWrt 24.10 的 ARM64 路由器说明，以 GL-MT6000 为例。请在路由器的软件包管理里安装 imOK。发布版本与测试范围见[项目 README](../../README.md)。

首次使用依次完成 **安装 imOK 插件 → 安装 WARP 运行环境 → 注册路由器 → 保存出口与接管范围 → 开启并验证**。前四步保持 imOK 总开关关闭。以下按钮名称以 v0.2.38-36 为准。

## 公开正式版分享包

从 [GitHub 最新正式发布](https://github.com/routepilot-lab/imok/releases/latest) 下载 `imOK-<版本号>-install-kit.zip`。压缩包包含完整插件 IPK、公开源码、使用／安装说明、更新记录、许可与校验文件。解压后先阅读 `开始阅读.md`。已有兼容环境只需升级 IPK。

公开分享包不含第三方 WARP 运行环境。[历史手动安装流程](../../docs/HISTORICAL_MANUAL_INSTALL.md)适用于含运行环境的个人安装包。本地测试包请核对其 IPK 文件名和对应测试记录。

## 安装矩阵

| 情况 | 操作 |
| --- | --- |
| 新设备，没有运行环境 | 用 iStore 上传首次安装文件（如发行包附带），再到「WARP 安装与更新」查看进度。也可在 LuCI 刷新软件包列表、上传 IPK，再打开该页面开始安装 WARP |
| 已有 `/opt/routepilot/runtime` | 只升级当前 IPK，保留原注册与配置，不重装运行环境 |
| 缺系统依赖 | 从与设备当前固件匹配的软件源补齐，由软件包管理检查依赖 |
| 想换新路由器 | 导出非凭据配置，新设备独立登录；导入后保持关闭，核对入口、出口和接管范围后手动启用 |

自动准备 WARP 运行环境需要约 1.6 GB 可用存储。已有兼容环境请使用上表的升级路径。

## 1. 安装 imOK 插件和系统依赖

先确认路由器能通过宽带正常联网。解压安装包并核对附件校验值。在 iStore「手动安装」上传安装包附带的 `imOK-版本-first-install.run`。它会安装 imOK 插件和固件缺少的系统组件，例如 Python。符合条件的全新路由器会在插件安装完成后开始后台安装 WARP。刷新 LuCI，在「服务」里找到 imOK。

首次安装文件优先尝试清华大学 TUNA 镜像。依赖未备齐时，依次尝试南京大学镜像和 OpenWrt 官方源。软件源版本和架构跟随当前固件，索引必须通过签名校验，原有软件源文件保持原样。

如果只有 IPK，或设备没有 iStore，在 LuCI「系统 → 软件包」先点「更新列表」，成功后上传并安装本版 IPK。

## 2. 安装 WARP 运行环境

1. 打开 **「WARP 安装与更新」**。如果后台任务已启动，等页面显示下载、校验和安装结果。
2. 如果未开始，点「自动下载并安装 WARP」，再确认「开始下载并安装」。安装失败时先看页面原因，再按提示重试。可复用校验合格的文件。需要单独下载、重新下载或确认分步安装时，展开「高级：查看下载文件与分步安装」。
3. 看到 **「WARP 已安装」** 和路由器内的 WARP 版本后，点「下一步：登录 Cloudflare 账户」。这里确认的是运行环境。账户注册和隧道连接各有自己的状态。

初次设置可以保留启动 DNS 的默认值「自动优选」，直接进入下一步。需要查看时，到 **「DNS → 高级 · WARP 启动解析」**。WARP 启动时会先尝试宽带下发的 DNS，并在需要时尝试备用服务器。详见 [WARP 安装与更新](../../docs/WARP_RUNTIME.md)。

## 3. 注册路由器到 Cloudflare

1. 到 **「Cloudflare 配置中心 → 账户与协议」**，填写并保存自己的 Cloudflare Zero Trust 团队名称。
2. 点「准备登录环境」，等「登录环境已就绪」，再点「邮箱登录」。在打开的 Cloudflare 页面，用团队允许的邮箱完成验证。
3. 如果浏览器询问是否打开电脑上的 Cloudflare 应用，点「取消」。在成功页右键选择「查看网页源代码」，搜索 `token=`，复制含授权链接的整行。回到 imOK 粘贴后，立即点「注册此路由器」。也可粘贴完整授权链接或 `token=` 后的令牌，imOK 会处理多余符号。临时凭据只粘贴到 imOK。
4. 看到「路由器已注册」后，等待自动读取账户出口。失败可点「重新检查账户」。只有目录已返回可选网络，账户页才会提示前往「出口与分流」。保存出口后，可先在总览检测路由器能否通过该出口联网。

## 4. 保存出口与接管范围

在 **「出口与分流」** 选择「主线路代理出口」。如果列表还没加载，点「刷新账户出口（只读）」。再选接管范围，点「保存并应用」。

- **按设备选择**。到「设备」添加或编辑策略，确认设备名称和地址，启用至少一台需要代理的设备，选择代理模式后再次「保存并应用」。「保持原样，不接管」的设备会继续按原路径联网。
- **所选局域网**。勾选要接管的 LAN 接口，确认 Wi-Fi 或网线设备位于该网络。

首次设置可保留「主线路入口」的「默认：官方自动」。

## 5. 开启 imOK 并检查联网

1. 到 **「总览 → 首次设置」**，在登录准备期间点「仅检测路由器 WARP 出口」，核对返回的 IPv4 和地区。测试会临时连接路由器的 WARP，局域网设备仍走原路径。若测试失败，先按总览提示排查。
2. 准备好后点「结束登录准备」，等按钮变成「开启 imOK」后手动开启。等待「当前配置已确认应用」和「隧道已连接」。
3. 点「检测实际出口地区」，核对路由器观察到的 IPv4 和地区。再用一台已接管的电脑或手机打开按策略应走代理的网站，确认该设备也能上网。
4. 分流 DNS 运行后，到 **「DNS」** 点「检测当前 DNS 解析」。需要测速度时再打开 **「总览 → 检测与测速」**。该测速从路由器发起，终端速度可在终端上另测。

## 卡在哪一步就检查哪里

| 页面提示 | 先检查 |
| --- | --- |
| 软件源更新失败，或缺少 Python 等系统组件 | 确认路由器能联网，核对报错的软件源、包名和固件版本。索引签名验证失败时先处理该软件源。 |
| imOK 已装好，WARP 未安装 | 打开「WARP 安装与更新」看进度或失败原因。尚未开始时，点「自动下载并安装 WARP」。如果是在高级区域选择了分步下载，校验完成后点「确认安装到路由器」。 |
| WARP 显示已安装，版本检查失败 | 已安装版本可在本页查看。检查更新需要访问版本源。账户登录与连接状态分别在「账户与协议」和「总览」确认。 |
| 邮箱授权过期 | 从 imOK 重新打开邮箱登录，验证后复制新凭据并尽快提交。 |
| 保存提示权限不足 | 用有写权限的 LuCI 账户退出并重新登录，再核对设置后保存。 |
| 路由器出口检测按钮灰色 | 确认路由器已注册，保存了主线路出口，并且仍在登录准备阶段。 |
| 请启用设备策略，或等待核对设备地址 | 检查「设备」里有启用的代理策略，并确认对应设备在线、地址匹配。 |
| 测速或 DNS 按钮灰色 | 先看总览的开关、应用和连接状态。测速需要运行中的线路，当前 DNS 检测需要分流 DNS 已启动。 |
| 已开启但连接失败 | 看总览「连接状态」下面的具体原因，按提示检查设备、出口或线路。 |

完整首次安装、APT 升级和恢复仍待在独立同款设备验收。各版本实测范围以[硬件验收记录](../../docs/HARDWARE_ACCEPTANCE.md)为准。

## 正常升级

先保留当前 IPK、私有配置备份和身份/配置哈希。只上传当前 IPK 或在设备运行 `opkg install /已校验的新版本.ipk`；可能短暂重连。不要执行重注册、删除运行环境或恢复整份旧系统设置。升级后刷新或重新登录管理页以更新旧会话菜单，核对显示版本、原出口、入口偏好、设备范围和 HTTPS，旧页面不能在后台自动换脚本。

规则管理中的个人新增与排除独立持久保存，普通插件更新和订阅更新不会清空；相关文件已纳入系统升级保留范围。当前 v3“导出配置”不包含这些个人覆盖，换设备前需另行备份，不能把普通设置导出当作完整规则迁移。

失败时使用备份的上一版本 IPK 明确降级并核查当前运行态；配置未变且没有新数据格式变化时才可按记录回滚。不要为回滚直接清空系统防火墙或覆盖 network/firewall/dhcp、SSR 配置。

## 恢复阻断

入口事务、持久恢复阻断、历史应用结果和恢复审计目录属于故障证据。固件保留清单包含这些证据；新恢复请求有启动实例和短时确认限制，不能跨重启自动重放。

完整原事务、原出口和当前客户端入口一致时，配置中心显示“受控恢复原入口并验证”。重新读取状态，输入 RESTORE 并确认后，后台只恢复原事务入口，在撤回接管后重连并核对原预期出口；验证、存储或上下文检查失败会继续阻断。操作过程中可能宽带直连。总开关关闭时也会临时启动客户端验证，完成后仍保持关闭、不接管设备；只有明确确认才执行。成功会保存原证据和解除结果。

按钮不可用时，不删除 `endpoint-recovery-block.json`、`endpoint-transaction.json` 或 `endpoint-applied.json`。先确认存储空间、文件可读性、当前组织/出口 UUID、原事务来源及客户端状态；保存受限的原始证据。证据损坏、缺基线、外部修改入口或出口不一致时，自动恢复会拒绝；需按该设备的私有备份与原安装记录制定人工恢复，不能猜测或伪造 baseline。若管理链路也受影响，先通过已准备的独立有线/本地入口处理。

本轮自动化或隔离检查不代表真实断电、固件升级、多 LAN 或手机速度通过；每一类以实际验收记录为准。
