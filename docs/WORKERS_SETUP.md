# Workers 备用线路完整设置（0.2.24）

入口：LuCI → 服务 → RoutePilot → Cloudflare 配置中心 → Workers 备用与 API 授权。已有主线路、出口与分流不变，备用不自动接管。分为部署、PROXYIP、优选和独立测试四步；默认展开第一个尚需处理的步骤，手动回看会保留。

## 节点和每一步结果在哪里

第五组顶部固定显示“备用节点与云端部署记录”：当前保存的备用节点、验证域名 / 连接入口、是否正在使用，以及本路由器创建的 Worker 名称、绑定域名、上传 / 绑定 / 保存状态。这里只读展示；一台路由器当前只保存一个供启用的备用节点，多个本机云端项目的部署记录可以同时显示。

每步有独立结果区及真实进度。① 显示项目核对 → 上传 / Worker 存在 → 子域名绑定 → DNS / HTTPS 证书；等待证书不等于失败。② 显示检测完成数及逐项结果，检测通过后仍需明确应用顺序。③ 显示已测入口数及推荐结果，推荐不会自动应用。④ 显示五项独立检测，只有有效证据才能手动启用。顶部“最近操作结果”在自动展开下一步后仍保留。

新任务先显示提交 / 接收确认及已等待秒数，旧成功标志不能当作新任务完成。状态未知、API 拒绝、域名冲突和证书等待分别提示；没有后台证据时不会假造完成百分比。结果过期或节点改变会明确标记，需要重新检测。

## 创建受限 API 令牌

打开 [Cloudflare API 令牌](https://dash.cloudflare.com/profile/api-tokens)，创建自定义令牌：

- 账户 → Workers Scripts → 编辑，仅选择自己的目标账户。
- 区域 → Zone → 读取；区域 → DNS → 读取；区域 → Workers Routes → 编辑，仅选择要绑定域名的区域。
- 设置合适的到期时间，复制令牌，仅在路由器本页私密输入框填写。不要发到聊天或放进普通配置备份，不使用 Global API Key。

账户 ID 可以留空。填写令牌，点击「保存令牌并读取账户 / 域名」，从令牌可读、且有有效域名的账户中选择；首次读取会取得当前令牌授权的全部有效根域名；选择账户时在本地筛选，不自动保存或改变绑定。也可在折叠项手工填写账户 ID。

已保存令牌后，可点击「刷新账户与根域名（只读）」重新读取，不需要重复保存表单。目录单独私密缓存，刷新网页不会只剩区域 ID，检查部署也不会覆盖目录；显示读取时间，15 分钟后提示历史目录。只有令牌授权且已生效的根域名可见，不能把目录可读当作已获部署权限。更换或清除本机令牌会清除旧目录；页面展示的账户 / 域名选择在明确保存前不会落盘。

选择根域名，例如 `example.com`，填写子域名前缀 `backup`，页面自动组成 `backup.example.com`。填写 `routepilot-` 开头的新 Worker 名称，先检查名称和子域名占用，再一键创建和绑定。根域名须已在 Cloudflare 生效；Worker 和子域名不用预先创建。只能读到令牌授权范围内的域名，没有结果时检查账户、Zone 读取权限与域名状态。

当前 [Workers 授权说明](https://developers.cloudflare.com/workers/authorization/workers/)要求变更路由或自定义域名具备区域 Workers Routes Write；令牌指引一并包含该项。绑定使用 [Workers Custom Domains API](https://developers.cloudflare.com/api/resources/workers/subresources/domains/methods/update/)，由 Cloudflare 创建记录和证书，不直接改写其他 DNS 记录。API 请求按 [Worker 模块上传接口](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/update/)构造。令牌按权限限制账户与区域；本插件仍会检查项目和域名冲突。

## 部署与设置为备用

只创建新项目或更新本机归属记录匹配的项目；不覆盖账户已有的其他 Worker，不覆盖现有 DNS 记录或其他服务的域名绑定。部署记录在上传前保存身份，重试保留同一个连接 UUID。没有升级付费计划的操作。

状态分别显示：已保存、正在检查、上传、绑定、等待 DNS/证书、HTTPS 就绪。API 返回成功不等于证书已生效，证书就绪也不等于代理网站已通过。证书未就绪时稍后点击检查状态，不关闭 TLS 验证。

部署就绪后，点击「将新部署设为备用节点（不启用）」，新部署的节点需重新逐项检测 PROXYIP、应用顺序，再做整条线路独立检测，最后由用户手动启用。Cloudflare API 令牌和连接 UUID 均不进入普通 UCI、普通导出、公开状态或命令参数。清除本机令牌不会撤销远端令牌，也不删除已部署线路；需要撤销时在 Cloudflare 操作。

## 公共转发 PROXYIP 候选

最多 6 项，逐项填写公网主机:端口、来源说明和可选公开 HTTPS 来源链接，可启用、停用、删除、上下移动。启用顺序为主用、备用 1、备用 2。来源是填写者声明，不是维护方背书；默认项仅来自 cmliu 上游文档示例，不宣称最快或长期稳定。

先保存，再逐项强制转发测试。每项只使用指定候选，禁止直连目标或换其他候选替它通过，验证 `www.cloudflare.com` 和 `speed.cloudflare.com` 的 HTTPS，并另测 64 KiB 真实下载。公共 PROXYIP 不等同通用 VPS：本次实测默认候选转发这两个 Cloudflare 目标成功，但强制转发 Google/GitHub 时 TLS 失败，因此不能拿此失败判定它所有转发能力失效。Google/GitHub 可用性在整条备用线路独立检测中验证。

所有启用项须在当前节点、同次开机、5 分钟内通过，才能应用到备用节点。保存/应用均不启用备用，不改主线路或 UCI 分流。候选单独增删、调整顺序不要求重建 Worker；旧版 Worker 会明确提示先更新模板，不会把检测未执行当成通过。

需要公共转发时按顺序建立连接，当前 Worker 实例内对连接失败项暂避 30 秒；全都暂避时会重新尝试列表。首包开始写入后不向其他候选重放用户载荷，已建立会话中断需重新连接，不保证无缝续传。域名可解析出不同实际服务器，测试不能证明所有后端长期可用。实例切换记录是本次查询命中的局部实例，不是全局统计。

## 自动优选入口

无需 API 令牌也可以测试已经导入的 Workers 线路。点击「开始自动优选」，最多测 8 个 Cloudflare 公网 IPv4 入口：当前入口、域名解析结果及有限种子地址，均受 [Cloudflare 官方 IPv4 网段](https://www.cloudflare.com/ips-v4)约束。

每个入口均使用相同的 Worker 域名/SNI/UUID，通过独立 loopback Xray 实际验证 Google、GitHub 和 64 KiB 下载。只有两个网页均成功的候选才参与推荐，按两站平均响应耗时排序，短测下载为参考。结果只代表本次小样本，不是全网最优、国家定位或带宽上限。

优选不会自动改动入口。点击「应用推荐入口（不切换）」才保存到备用节点；保留证书域名，清除旧检测凭据，之后重新独立检测。结果绑定节点指纹、开机标识及单调时间，5 分钟有效。不改变 UCI 出口、设备策略、DNS 配置、全局缓冲或主线路。

## GitHub 检测

旧版用 `api.github.com/zen`，发生过约 4 秒的失败，但未记录 curl 错误码和各阶段耗时，无法据此确证根因。两入口 14 次复测均成功，没有证明该线路永久故障，也没有证明问题已永不复发。

新版检测 `github.com/robots.txt`，对连接、TLS 或传输错误最多重试一次；证书错误不重试，HTTP 403/429 显示访问受限。保存每次尝试的 curl 错误码、连接/TLS/首字节/总耗时，明确提示重试后成功。部分项目失败时显示「基础连通可用，但部分项目未通过」，不再笼统显示全部通过。
