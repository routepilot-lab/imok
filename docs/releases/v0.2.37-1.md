# imOK 2.0 · WARP 安装与更新

**v0.2.37-1 预发布版。** 让第一次使用时的安装顺序更清楚，也让已经运行的路由器知道何时有新版。

已有环境上的插件更新、真实版本读取、官方目录检查和每日调度已在 ARM64 OpenWrt 24.10 路由器验证。**全新 WARP 环境安装、APT 升级和运行环境回滚仍待独立实机验收**，因此本版保留预发布标记；[v0.2.36-1 正式版](https://github.com/routepilot-lab/imok/releases/tag/v0.2.36-1)继续保留。

## 从哪里开始？

进入 **imOK → WARP 安装与更新**。装好插件以后，先在这里确认路由器有没有 WARP，再登录自己的 Cloudflare 账户、选择已部署出口，最后手动开启。

- **自动检测环境。** 识别系统、处理器、空间和必要组件，不让普通用户猜架构或寻找运行包。
- **自动准备官方文件。** 点击准备后，从固定官方来源取得 Debian ARM64 基础环境和 WARP，核对大小、哈希、签名及依赖。下载完成不等于安装完成，仍需单独确认。
- **定期检查，只提示新版。** 默认每天检查，也可选择三天、每周或关闭。不会自动升级、重启 WARP 或切换出口。
- **维护先备份，再确认。** 安装、升级与恢复有独立确认；现有环境不能被首次安装覆盖。升级在副本中校验，保留原环境和身份，失败时阻止盲目启动。
- **离线导入作为高级备用。** 不再把“上传运行环境包”当作默认流程。

自动准备暂限 ARM64 OpenWrt 24.10 / Debian 12，需约 1.6 GB 可用空间。官方源不可达、文件不符或环境不兼容时停止，不关闭 HTTPS 或签名校验来强行安装。[完整操作与边界](https://github.com/routepilot-lab/imok/blob/main/docs/WARP_RUNTIME.md)。

## 页面和交互

插件统一为六个主入口、十四个页面，继续继承 Argon 字体。修复真实 LuCI 将 `disabled=false` 仍视为禁用属性的问题；检查、刷新、保存及取消按钮按真实条件启用。一级导航有明确排序与选中状态，已确认的请求不再残留“正在提交”。

原有规则、个人覆盖、手机独立身份、私密订阅、DNS、Workers 手动备用和备份迁移继续保留。没有改变路由算法、UCI 数据格式或已有默认网络策略。

## 已有路由器怎么更新？

先保留旧 IPK 和私有备份，再校验附件、安装新 IPK。**普通 IPK 安装会执行插件维护脚本，可能短暂重连**，远程操作应先准备独立可恢复的管理连接。已有 WARP 环境只更新插件，不重新注册、不覆盖原运行环境。

本次维护者现场采用受控文件更新，保留原线路进程；这不代表标准 IPK 升级也能保证不断线。热更新后，运行中主进程仍使用已加载代码；安排 WARP 运行环境写入维护前，应在独立本地管理连接下正常重启插件加载新保护，再关闭总开关进行维护。[安装与回退说明](https://github.com/routepilot-lab/imok/blob/main/packages/luci-app-routepilot/INSTALL.zh-CN.md)。
