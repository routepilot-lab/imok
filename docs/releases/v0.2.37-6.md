# imOK v0.2.37-6 · 旧路由器测试版

这是完整插件升级包，适合已有兼容 OpenWrt 和 WARP 环境的旧路由器。保留已保存的出口、设备策略、规则和注册。安装过程中 imOK 服务可能短暂重连。使用独立的有线管理入口，Mac mini 等依赖代理出口的设备可以继续留在日常使用的路由器上。

## 先备份旧路由器

1. 用一台备用电脑连接旧路由器的 LAN，核对管理页显示的设备。保存当前插件版本、总开关和各设备保护设置。留一台设备用于测试，避免正在运行的应用在关闭 imOK 时走宽带直连。
2. 在旧路由器的 LuCI 进入「系统 → 备份／升级」，生成并下载系统备份。再到「imOK → 备份迁移」导出普通配置，便于核对设备策略。普通导出不包含客户端注册、订阅凭据和个人规则覆盖。
3. 通过旧路由器的 SSH 或由维护者另外备份 `/etc/config/routepilot`、`/etc/routepilot/` 和现有 WARP 私有注册目录。确认备份可打开，并保留到电脑上的私有目录。备份里可能有凭据，请和可分享的安装包分开保存。保留上一版 IPK 或与该机现有补丁对应的回滚副本。
4. 校验本包里的 `SHA256SUMS`，再上传 `luci-app-routepilot_0.2.37-6_all.ipk` 到旧路由器的软件包页面。已有 WARP 环境只升级插件。若旧路由器正处于保护冲突状态，先在总览确认总开关已经关闭，再安装测试版。

## 验收一 · 单设备保护冲突

1. 保持旧路由器已有的流量卸载状态。选择一台已启用代理策略的测试设备，确认它当前可以上网，记录总览和设备原设置。
2. 到「配置中心 → 设备 → 编辑」，选择「为此设备启用」，点设备编辑框里的「保存」。如果软、硬件卸载开启，或运行中的流表仍然存在，应当直接提示「本次未保存」。
3. 用同一台设备继续打开网页，核对实际出口和 DNS。关闭编辑框再打开，核对保护选项仍为原值。测试记录同时标明旧路由器上的卸载状态和页面提示。若卸载原本已经关闭，跳过冲突用例，避免为了制造冲突改动正在使用的防火墙。

## 验收二 · 手动关闭 imOK 后正常联网

1. 在总览确认旧路由器的 imOK 正常运行。用测试设备确认代理出口和普通 DNS 解析。若旧路由器原本关闭流量卸载且保护可用，可先对测试设备开启保护再测试关闭。
2. 点击「关闭 imOK」，等总览确认关闭和撤回保护。测试普通 DNS 与 HTTPS 是否恢复由路由器原有规则处理。此时可能使用宽带真实 IP。
3. 确认出口和设备策略仍保存在配置里。重新开启后应该沿用原值。若已保存保护但流量卸载发生冲突，应提示失败并保持总开关关闭。

## 回滚

发现异常先保持旧路由器的有线管理连接。在新版总览关闭 imOK，确认保护已撤回。再将总设置和所有单设备保护开关临时设为关闭，以免早期版本在插件关闭时继续拦截外网。

保留配置直接回退插件时，在旧路由器的管理员终端运行 `opkg --force-downgrade install /路径/旧版.ipk`，刷新 LuCI 并核对版本、网络和设置。回退包的安装也可能短暂重新载入服务。需要恢复个别私有配置时，使用升级前备份核对并按需恢复，避免把旧版的保护冲突原样恢复。配置和注册本来就一致时，无需覆盖私有数据。

本版已通过本地自动化、LuCI 契约和可复现构建。冲突拒绝保存、关闭清理和设置保留均有隔离测试，以上两项旧路由器验收仍待实际操作。
