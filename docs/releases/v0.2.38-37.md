# imOK v0.2.38-37 · WARP 自动恢复与分流稳定性

<!-- release-status: stable -->

WARP 进程被系统终止后，imOK 会清理旧实例，按已保存的协议、出口和设备策略重新建立线路。

- 修正策略路由优先级冲突和迁移检查。核对实际转发路由后再接管，整网模式的 Cloudflare 客户端直连例外保留原范围。
- 补齐 IPv6 DNS 防绕过，修复全局及白名单模式的 DNS 分流、HTTPS 记录缓存和 WARP 启动解析核验。
- 撤销客户端身份时同步停用私密订阅，改善 Workers 备用线路的短时断流处理。删除 Workers 模板里不参与运行的长篇注释，插件 IPK 缩小至约 424 KiB。
- 改善 WARP 安装的证书与镜像回退，修正部分 LuCI 显示与轮询问题，减少流量统计空闲时的写入。

## 安装

- 全新设备使用完整 ZIP 内的 `first-install.run`。iStore 会补齐系统依赖，随后可在「WARP 安装与更新」查看在线安装进度。
- 已安装 imOK 的设备备份后上传同版 `luci-app-routepilot_0.2.38-37_all.ipk` 原地升级。已有线路可能短暂重连。
- 已卸载并保留旧设置的设备使用 ZIP 内的 `reinstall-cn-keep-settings.run`。
- 下载后用 `SHA256SUMS` 核对文件。支持范围和详细流程见 [安装指南](../INSTALL_KIT.md)。

## 验证

32 组本地检查通过。在 ARM64 Debian 隔离环境用真实 WARP 2026.8.2115.0 三次终止进程，虚拟局域网设备均在约 14–16 秒恢复访问，保持同一公网 IPv4。实验使用独立的 Cloudflare 默认出口。

在 GL-MT6000 / OpenWrt 24.10.4 上验证原地升级，原配置、WARP 注册身份和实际公网出口一致，8 项 DNS 查询通过。空白路由器完整首装与注册、实机故障注入仍待验证。路由器曾遇到的内存暴涨根因仍未确认。
